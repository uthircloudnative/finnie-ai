# Agentic Observability & Tracing Guide

As LLM applications move to production, seeing "inside the black box" of an agent graph becomes critical. This document outlines the industry-standard approach for achieving full observability in Finnie AI.

## The Two Pillars of Agentic Observability

To fully understand a request's lifecycle, you need two layers of tracing working together:
1. **Application Tracing**: Tracking the request from the FastAPI endpoint through your custom Python code, databases (SQLite), and external APIs (AlphaVantage).
2. **LLM Tracing**: Tracking the specific prompts, token usage, tool calls, and LLM reasoning steps inside LangGraph/LangChain.

---

## 1. Application-Level Tracing (Trace IDs)

The goal here is to generate a unique `trace_id` the moment a user clicks "Send" and ensure that ID is attached to every single log line generated by that request.

### Implementation Blueprint:
1. **Middleware Generation**: Create a FastAPI Middleware that intercepts all incoming requests and generates a unique UUID (the `trace_id`). 
2. **Context Variables**: Use Python's built-in `contextvars` module to store this `trace_id`. Unlike global variables, `contextvars` are safe for asynchronous concurrent requests (which FastAPI uses heavily).
3. **Custom Logger**: Configure Python's standard `logging` library with a custom formatter that reads the `contextvar` and automatically prepends `[TraceID: 1234-abcd]` to every `logger.info()` or `logger.error()` call.
4. **Graph State Injection**: Add `trace_id` to the `FinnieState` TypedDict. This ensures that as the state moves from the Supervisor to the Analyst to the RAG database, the exact same ID is accessible to any node.

**Why this matters**: If a user reports a bug, you simply ask for their Request ID (which the UI can display), drop that ID into Datadog, ELK, or CloudWatch, and see the exact chronological log of the entire backend execution.

---

## 2. LLM Tracing (LangSmith vs. Langfuse)

To track the actual AI behavior (prompts sent, tokens consumed, latency, RAG retrieval quality), the industry standard is to use a specialized LLM observability platform. 

### Option A: LangSmith (Native & Recommended)
Since Finnie AI is built heavily on **LangGraph** and **LangChain**, LangSmith is the first-party, zero-friction choice.

*   **How it works**: It requires **zero code changes**. You simply set environmental variables:
    ```bash
    LANGCHAIN_TRACING_V2=true
    LANGCHAIN_API_KEY=ls__...
    LANGCHAIN_PROJECT="Finnie-AI-Prod"
    ```
*   **What it does**: LangChain automatically detects these variables and intercepts every LangGraph node transition, every LLM `invoke()`, and every ChromaDB retrieval. It visualizes the entire multi-agent loop in a beautiful tree UI, showing exactly what prompt the Supervisor generated vs. what the Portfolio Analyst generated.

### Option B: Langfuse (Open Source Alternative)
Langfuse is the industry darling for open-source, self-hosted LLM observability.
*   **How it works**: They provide a native LangChain callback handler. When invoking your LangGraph, you simply pass the Langfuse handler in the `config` dictionary.
*   **What it does**: It provides very similar tracing to LangSmith but allows you to own your data entirely if you deploy it on your own infrastructure.

## 3. Tying It All Together (The Golden Thread)

The true "Holy Grail" of observability is linking your Application Trace (from FastAPI) to your LLM Trace (in LangSmith/Langfuse). If you see a timeout error in your standard application logs under `Trace-XYZ`, you want to click a link and see the exact LangSmith LLM run for `Trace-XYZ`.

### How to link them:
When you call your LangGraph orchestrator from FastAPI, you pass your custom `trace_id` into the LangChain **run metadata**.

*Conceptual implementation:*
```python
# Inside your FastAPI route:
trace_id = get_current_trace_id()

# Pass the trace_id into the LangGraph config map
config = {
    "configurable": {"thread_id": user_id},
    "metadata": {
        "app_trace_id": trace_id,  # <--- The Golden Thread
        "environment": "production"
    }
}

# Invoke the agent graph
result = app_graph.invoke(state, config=config)
```

In LangSmith or Langfuse, you can now search directly by the `app_trace_id`.

## 4. Annotation-Driven Tracing (Deep Dive)

You are absolutely correct! While standard LangChain/LangGraph setup automatically traces LLM calls and graph node transitions, what happens if you have a complex internal Python function (like the `run_monte_carlo` engine or a custom API call to AlphaVantage) that isn't a native LangChain object?

That is where **Annotation-Driven Tracing** comes in.

### LangSmith: `@traceable`
LangSmith provides a `@traceable` decorator that you can place completely outside of the LangChain ecosystem on *any* Python function.

```python
from langsmith import traceable

@traceable(name="Monte Carlo Engine", run_type="tool")
def run_monte_carlo(initial_balance, target_amount, ...):
    # This entire Python function's inputs, outputs, and execution time 
    # will now nested perfectly inside your LangSmith trace tree!
    return sim_data
```

### Langfuse: `@observe`
Langfuse offers the exact same paradigm using their `@observe` decorator.

```python
from langfuse.decorators import observe

@observe(capture_input=True, capture_output=True)
def fetch_live_news(ticker: str):
    # This will create a discrete 'Span' inside your overarching Langfuse trace.
    return requests.get(...)
```

By adding these annotations to your "dumb" helper functions, your LLM traces become full-stack application outlines, preventing "blind spots" between the LLM and your raw Python utility code.

## Summary of Implementation Roadmap (Scenario B)
To achieve Full-Stack Observability where your API logs are seamlessly linked to your LangSmith/Langfuse traces, here is the exact implementation path:

1. **FastAPI Middleware**: Create `backend/src/utils/telemetry.py` containing a `TraceContextMiddleware` spanning requests to generate a UUID and bind it via `contextvars`.
2. **Context-Aware Logging**: Overhaul the standard Python `logger` with a custom formatter that extracts the `contextvar` and automatically prepends `[Trace-UUID]` to all `.info()`, `.warning()`, and `.error()` statements across the codebase.
3. **Graph Invocation Coupling**: In `backend/src/graph.py` (specifically in the `/chat` and `/goals/calculate` route handlers), grab the active `trace_id` and inject it directly into the LangGraph `config` under `"metadata": {"app_trace_id": trace_id}`.
4. **LLM Platform Setup**: Ensure `.env` includes `LANGCHAIN_TRACING_V2=true` and an API key (or equivalent variables for Langfuse).
5. **Annotation Coverage**: Select critical inner utility functions—such as `run_monte_carlo` or `yfinance` API calls in `backend/src/utils`—and decorate them with `@traceable` to ensure they are visually nested under the root request trace.
